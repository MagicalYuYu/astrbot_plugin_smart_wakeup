# v1.0.7 人格提示词优化交接文档

> 本文档面向人格提示词优化 Agent，提供插件 v1.0.7 新增功能对 LLM 上下文的影响说明，以及人格提示词的配合优化建议。

---

## 1. 插件 v1.0.7 新增功能概述

v1.0.7 引入了三项新功能，它们直接改变了 LLM 接收到的上下文格式和内容：

1. **在场用户感知**：在群聊上下文中标注近期活跃用户列表，并注入提示词约束 BOT 只对在场用户说话。
2. **对话关系标注**：将 BOT 消息统一标注为 `[BOT]`，并标注回复关系（`→ 回复`）和隐式回应（`回应BOT`），帮助 LLM 理解对话流向。
3. **图片上下文**：将图片消息以 `[图片: 描述]` 的形式注入上下文，使 LLM 能够"看到"群友发送的图片内容。

这三项功能的核心目标是**让 LLM 更准确地理解群聊语境**，从而减少误回复、漏回复和语境理解偏差。人格提示词需要配合这些变化，避免重复约束或产生冲突。

---

## 2. 插件注入的上下文格式变化

### 2.1 在场用户感知

**上下文变化：**

- 在 `<group_chat_context>` 顶部新增活跃用户列表行：
  ```
  [近期活跃]: 用户A, 用户B
  ```

**注入的提示词标签：**

插件在 `on_llm_request` 中注入以下 XML 标签：

```xml
<presence_awareness>
注意：只对近期活跃的用户说话，不要对不在场的群友发起对话。
上下文中标注了[近期活跃]用户列表，仅对这些用户做出回应和互动。
</presence_awareness>
```

### 2.2 对话关系标注

**上下文变化：**

- BOT 消息标注从 `[Bot名称]: 内容` 变更为 `[BOT]: 内容`
- 回复关系标注：`[用户A] → 回复[BOT]: 内容`
- 隐式回应标注：`[用户A] (回应BOT): 内容`

**注入的提示词标签：**

```xml
<conversation_guidance>
群聊中用户常省略主语，省略主语的句子通常指说话者自己。
例如「怎么突然就变成XX了？」通常意为「我怎么突然就变成XX了？」，
而非指他人。请结合上下文对话关系标注（→ 回复/回应BOT）正确理解省略主语的句子。
</conversation_guidance>
```

### 2.3 图片上下文

**上下文变化：**

- 启用图片上下文时：`[用户A]: [图片: 描述内容]`
- 未启用图片上下文时：`[用户A]: [图片]`（仅占位符）

图片描述由视觉模型生成，描述质量取决于模型能力。

## 3. 人格提示词需要配合的优化建议

### 3.1 在场感知配合

- ✅ 插件已注入 `<presence_awareness>` 标签，人格提示词**不需要**重复添加在场约束规则
- ✅ 人格提示词**可以**添加符合角色性格的补充规则，例如：
  > 如果想念不在场的朋友，可以自然地提起他们，但不要当作他们在场一样直接对话
- ❌ 人格提示词**不应**添加与插件约束矛盾的规则，例如"主动和所有群友打招呼"

### 3.2 对话关系标注配合

- ✅ 插件已注入 `<conversation_guidance>` 标签
- ✅ 上下文中 BOT 消息标注为 `[BOT]`，人格提示词应基于此标注进行引用
- ✅ 人格提示词**可以**添加：
  > 上下文中标注了(回应BOT)的消息是群友对你说的，请优先回应
- ❌ 人格提示词**不应**添加与标注系统冲突的规则

### 3.3 图片上下文配合

- ✅ 启用图片上下文时，LLM 能看到 `[图片: 描述]`
- ✅ 人格提示词**可以**添加：
  > 如果群友发送了图片并发表了评论，请结合图片描述理解他们的意思
- ❌ 人格提示词**不应**假设始终能看到图片——该功能可能被禁用
- ❌ 人格提示词**不应**添加"描述你看到的图片"之类的指令，因为 LLM 收到的是文字描述而非图片本身

### 3.4 省略主语问题

- ✅ 插件已注入 `<conversation_guidance>` 标签处理省略主语
- ✅ 人格提示词**可以**强化：
  > 当用户省略主语时，默认指代说话者自己
- ❌ 人格提示词**不应**添加冲突规则，例如"省略主语时指代你(BOT)"

## 4. 已知问题和局限

| 局限 | 说明 |
|------|------|
| 在场感知是提示词层面约束 | LLM 仍可能偶尔违反，对不在场用户发起对话 |
| 图片描述质量受限 | 描述质量取决于视觉模型能力，可能出现描述不准确或遗漏细节 |
| 对话关系标注基于时间窗口 | 隐式回应标注基于 5 秒时间窗口，快速连续对话可能产生误标注 |
| 图片识别依赖外部插件 | 系统图片识别依赖 group_chat_context 插件，如果该插件未启用则无法获取描述 |
| `[BOT]` 标注不包含自定义名称 | 上下文中 BOT 统一显示为 `[BOT]`，人格提示词中设定的名字不会出现在上下文标注中 |

## 5. 上下文注入完整示例

以下是 v1.0.7 之后 LLM 实际接收到的上下文示例，展示了所有新增标注：

```xml
<group_chat_context>
以下是自上次回复后的群聊消息（新增5条）：
[近期活跃]: 用户A, 用户B
[用户A]: [图片: 这是一张游戏角色截图，展示了角色属性面板]
[用户A]: 一眼阿尔弗雷德
[BOT]: 哈哈确实像，这属性也太离谱了
[用户B] (回应BOT): 怎么突然就变成这样了？
[用户A]: 你当Bot傻吗
</group_chat_context>

<presence_awareness>
注意：只对近期活跃的用户说话，不要对不在场的群友发起对话。
上下文中标注了[近期活跃]用户列表，仅对这些用户做出回应和互动。
</presence_awareness>

<conversation_guidance>
群聊中用户常省略主语，省略主语的句子通常指说话者自己。
例如「怎么突然就变成XX了？」通常意为「我怎么突然就变成XX了？」，
而非指他人。请结合上下文对话关系标注（→ 回复/回应BOT）正确理解省略主语的句子。
</conversation_guidance>
```

**解读示例中的关键标注：**

- `[近期活跃]: 用户A, 用户B` — 当前在场用户
- `[图片: 这是一张游戏角色截图...]` — 图片描述
- `[BOT]:` — BOT 自身发言
- `(回应BOT)` — 用户B 隐式回应了 BOT 的上一条消息
- `[用户A]: 你当Bot傻吗` — 无标注，属于普通发言，不直接回应任何人

## 6. 插件注入接口清单

以下是插件注入到 LLM 上下文中的所有 XML 标签和特殊标注：

| 标签/标注 | 类型 | 说明 |
|-----------|------|------|
| `<group_chat_context>` | XML 标签 | 群聊上下文容器，包含所有群聊消息 |
| `[近期活跃]` | 行内标注 | 活跃用户列表，位于上下文顶部 |
| `[BOT]` | 行内标注 | BOT 发言的统一标注，替代 Bot 名称 |
| `→ 回复[xxx]` | 行内标注 | 显式回复关系，标注消息的回复对象 |
| `(回应BOT)` | 行内标注 | 隐式回应标注，标识对 BOT 上一条消息的回应 |
| `[图片: 描述]` | 行内标注 | 图片消息描述，替代原始图片 |
| `<presence_awareness>` | XML 标签 | 在场感知提示，约束 BOT 只对活跃用户说话 |
| `<conversation_guidance>` | XML 标签 | 省略主语提示，指导 LLM 正确理解省略主语的句子 |
| `<natural_wakeup_context>` | XML 标签 | 唤醒类型提示，标识本次唤醒的触发方式 |
| `<aggregated_messages>` | XML 标签 | 聚合消息，将多条消息合并展示 |

**注意事项：**

- `<natural_wakeup_context>` 和 `<aggregated_messages>` 为 v1.0.7 之前已有的注入接口
- 所有 XML 标签均在 `on_llm_request` 阶段注入，位于系统提示词之后、用户消息之前
- 人格提示词优化时应避免与上述任何标签的功能产生冲突或重复
